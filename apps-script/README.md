# 課程清單與場次統計

總覽的「開課場次與學員人數」讀取 Google Sheet 的「課程清單」，四門課的卡片也顯示相同統計。問卷份數是回收量；學員人數由管理者登記，不以問卷推算。

## 更新現有服務

1. 在原本綁定 Sheet 的 Apps Script 專案，把原程式碼替換為 [Code.gs](Code.gs) 的完整內容。請勿把兩份程式同時貼入，以免重複宣告。
2. 選擇 `setupCourseSheet` 執行一次並授權，建立「課程清單」。已有分頁時不會覆寫資料；若自行建立，欄名請使用下表。
3. 在「課程清單」建立真實場次。範例資料只供格式參考，程式不會自動建立範例場次。
4. 部署 → 管理部署作業 → 編輯 → 版本選「新版本」→ 部署。沿用目前 Web App 的執行身分及可供學員存取的設定，網址不變。既有密碼與前後測工作表都保留，無須重新執行密碼初始化或封存問卷。
5. 發布更新後的網站檔案，再用總覽的「重新整理」載入清單。前後端需一起更新；新問卷需要新服務提供場次清單與收件確認。

將網站檔案推送至 GitHub 不會同步修改 Google Sheet 或 Apps Script。請另外完成上述建立清單與部署新版本的步驟；GitHub Pages 的發布依儲存庫設定執行。

## 有學員正在填答時

保留目前正式 Web App 的部署版本與網址，先在獨立測試專案驗證新版。若學員使用已部署的 `/exec` 網址，單純修改儲存庫檔案不會更新 Google 上的部署；正式啟用需另外選擇新版本並部署。

1. 建立另一份空白 Google Sheet，從它的「擴充功能 → Apps Script」開啟獨立測試專案。
2. 在測試專案的 `Code.gs` 整份貼上本資料夾的程式碼，確認可以儲存。請取代原檔內容，不要將新版接在舊版末尾；同一專案的其他 `.gs` 檔也不應重複宣告 `PW_SHEET`、`TZ` 等同名常數。
3. 只在測試專案執行 `setupCourseSheet`、`setupPasswordSheet`、`setupCourseAdmin`，確認能建立清單與管理權限欄位。測試 Sheet 使用測試資料與獨立密碼，不複製學員答案或正式密碼。
4. 測試通過後，在填答時段結束的空檔更新原正式專案，部署新版本並沿用原網址。保留原 Sheet，不要重建或清除問卷工作表。

GAS 原始碼目前以 ES2017 語法檢查，避開 `??` 與物件展開語法；這是語法相容性檢查，不等同於實際 Google 部署成功。若編輯器仍無法儲存，請記下紅色錯誤文字及行號，據此確認是否為語法、重複宣告或其他專案設定問題。

`setupCourseAdmin` 會先補足必要的列與欄，再新增管理權限；適用於曾被刪減列／欄的密碼表，保留原資料與既有權限。

## 管理者登入與同事維護

儀表板右上角新增「管理者登入」。登入成功後按鈕改為「課程管理」，可隨時開啟場次維護。初始登入畫面也有管理者入口，同事可直接登入管理功能。

環境負責人先完成一次權限設定：

1. 將本資料夾的完整新版 `Code.gs` 替換到原 Apps Script 專案並儲存。
2. 執行 `setupCourseAdmin`。它會在「密碼管理」分頁新增「管理課程（是／否）」欄位，保留原密碼、備註及登入紀錄。既有使用者預設為「否」，重跑不會清除已設定的權限。
3. 在 Sheet 中，把你與維護同事的密碼列設為「啟用＝是」、「管理課程＝是」。可為每位同事建立各自的密碼列，在使用者／備註欄記錄姓名；密碼請直接在 Sheet 設定，不要放入網站程式碼或聊天。
4. 部署 Apps Script 新版本，沿用原網址；網站也需發布這次更新。

同事日後的操作：

1. 按「管理者登入」，輸入已授予管理權限的密碼。
2. 按「新增場次」，選擇四門課之一，填上課日期、時間、人數、狀態及開放填答設定。場次ID會自動產生。
3. 按「建立場次」。確認服務完成儲存後，Sheet 與總覽會一起更新。
4. 修改時在場次清單按「編輯」，調整日期、時間、人數、狀態與填答開關，再按「儲存修改」。

既有場次的ID與課程固定，避免已發出的問卷連結或前後測配對失效；要換成另一門課請新增場次，原場次可設為「取消」。取消或關閉填答會保留問卷與分析資料。

「重新載入清單」保留正在編輯的內容。若同事或 Sheet 已先修改同一列，伺服器會拒絕用舊版本覆寫；請重新載入清單、重新按該列「編輯」確認最新內容，再進行修改。

管理者登入有效時間為30分鐘，登入憑證只保存在目前頁面的記憶體。重新整理頁面需再次登入；登入過期時未儲存的內容仍保留。停用密碼、修改密碼或取消管理權限後，既有管理憑證也會失效。只有查看權限的密碼仍可使用原儀表板登入，不能修改清單。

管理者密碼以POST傳送，登入結果以短效的隨機收件識別碼讀取；後續操作使用伺服器產生的登入憑證。每次清單讀取、儲存及儲存確認都重新驗證權限，不依賴畫面按鈕是否顯示。新增與修改經儲存確認後才顯示完成；網路中斷時請重新載入清單確認，避免把尚未確認的操作當成已完成。

## 課程清單欄位

| 欄位 | 如何填寫 |
| --- | --- |
| 場次ID | 每場唯一，例如 `echo-20261014-01`。同一天兩場用不同 ID。問卷使用後不要修改 ID。 |
| 課程 | 選「心臟超音波」、「內視鏡」、「腹部超音波」或「腹腔鏡」。 |
| 上課日期 | 實際課程日期，填完整西元年月日，例如 `2026-10-14`。 |
| 開始時間 | 可選填，例如 `13:00`，用於區分同一天的不同場次。 |
| 學員人數 | 非負整數。預定場次可填預計人數；上課後改成實際人數。留白代表待填，`0` 代表確認沒有學員。 |
| 狀態 | 「預定」、「已開課」或「取消」。完成開課後由你改成「已開課」，不會因日期已過自動計入。 |
| 開放填答 | 「是」或「否」。前測提前填寫時就設「是」；補填後測期間也保持「是」。關閉後保留既有分析。 |

範例（請替換成你的實際場次與人數）：

| 場次ID | 課程 | 上課日期 | 開始時間 | 學員人數 | 狀態 | 開放填答 |
| --- | --- | --- | --- | --- | --- | --- |
| echo-20261014-01 | 心臟超音波 | 2026-10-14 | 13:00 | 6 | 預定 | 是 |
| endo-20261020-01 | 內視鏡 | 2026-10-20 | 11:00 | 6 | 預定 | 是 |
| abd-20261020-01 | 腹部超音波 | 2026-10-20 | 15:30 | 6 | 預定 | 是 |
| lap-20261105-01 | 腹腔鏡 | 2026-11-05 | 13:00 | 5 | 預定 | 是 |

「已開辦場次」只數狀態為「已開課」的有效列；「學員人次」加總這些場次的學員人數，同一學員上兩場計兩人次。空白或不合法人數會顯示待填，不冒充完整總數。預定場次另列；取消場次不計入兩者。重複 ID 或缺少必要資訊的列不計入，總覽顯示修正提示。課程清單統計不受問卷的「身分」篩選影響，因為清單沒有各身分人數。

## 提前填前測與同一天多場

學員先選課程、再選真正上課的場次。問卷會記錄「場次ID」、「上課日期」和實際收到問卷的「時間戳記」。例如 10/10 填前測、10/14 上課後填後測，兩份問卷仍屬於 10/14 的同一場。

總覽可展開「查看場次清單與填答連結」，直接取得該場前後測連結。也可使用：

```text
pretest.html?course=echo&session=echo-20261014-01
posttest.html?course=echo&session=echo-20261014-01
```

課程代碼：`echo` 心臟超音波、`endo` 內視鏡、`abd` 腹部超音波、`lap` 腹腔鏡。選好場次後產生的海報 QR Code 會包含場次 ID 與上課日期；未選場次的通用海報讓學員自行選擇。

前後測配對使用「課程＋場次ID＋去除空白的姓名」；同一人同一場同一階段重複填答取最後一次，不同場次保留。同名不同人的辨識仍沿用現有姓名規則，需管理者確認。

## 既有問卷資料

不會以「時間戳記」猜測上課場次。舊資料仍保留在問卷份數與分布統計，場次篩選會出現「未指定場次」，不參與配對提升統計。

先建立歷史課程清單，再在原前後測工作表新增「場次ID」欄，依實際出席紀錄補填。也可補「上課日期」：同一課程同一天只有一場時能配對；同一天有多場請一定填 ID。已填 ID 時以 ID 為準，不會把錯誤 ID 自動改配到其他場。清單場次設「取消」仍保留其問卷與分析，但不計開課總數且不可新填答。

## 資料介面與驗證

- `?action=sessions` 公開回傳開放填答的場次、課程、日期、時間與狀態，供學員選擇；不包含人數、姓名、答案、收件 ID 或管理密碼。
- `?pw=…` 沿用密碼保護，儀表板讀到「課程清單」與問卷資料，密碼分頁永遠不回傳。
- 問卷 `doPost` 只允許四門課的前後測工作表，確認場次屬於該課、開放填答且未取消，課程日期以清單為準。課程管理則使用獨立的 `admin-login`、`admin-save`、`admin-logout` 操作，儲存清單必須具有管理權限。
- 問卷沿用 `no-cors` POST，再以隨機收件識別碼讀取 `?action=receipt&token=…` 確認成功才顯示完成。收件狀態快取六小時；同頁面相同答案重試沿用識別碼，工作表的「收件ID」避免重複追加。重新整理頁面後不會保留重試識別碼，若收件確認中斷，先由管理者確認資料再重新填寫。
- 不需要額外套件或建置，使用靜態伺服器即可開發。`node tests/sessions.test.cjs` 驗證清單規則與 Apps Script 模擬服務；`python3 tests/browser_smoke.py` 使用已安裝的 Playwright 與 Chromium 驗證前端。測試只使用模擬資料，不會連線或寫入正式 Sheet。

實際部署後，請確認場次能載入、總覽與手動登記一致，再用你授權的測試場次驗證收件。沒有直接連上正式 Sheet 的測試無法證明正式部署已更新。
